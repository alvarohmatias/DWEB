Arquitetura em Camadas

Na Arquitetura em camadas, uma das abordagens mais tradicionais os módulos são dispostos de maneira
hierárquica, de modo que determinado nível utilize apenas os serviços fornecidos pelo nível
imediatamente inferior. Essa abordagem manifesta-se com frequência na arquitetura em três camadas,
típica de sistemas corporativos, que segrega a aplicação entre a camada de interface com o usuário,
a camada de lógica de negócio para a execução das regras do sistema e a camada de persistência para
armazenamento no banco de dados.

Model View Controller (MVC)

O padrão Model-View-Controller (MVC) propõe a separação formal do sistema em três componentes
fundamentais: a Visão, responsável pela apresentação; o Controlador, encarregado do tratamento de
eventos e entradas do usuário; e o Modelo, que detém a lógica de domínio e o gerenciamento dos
dados. A desacoplagem entre apresentação e lógica permite múltiplos pontos de exibição para um mesmo
modelo e simplifica os procedimentos de teste. No contexto moderno do desenvolvimento web, essa
dinâmica reflete-se no funcionamento das Single Page Applications (SPAs), nas quais o código é
executado no próprio navegador e realiza atualizações de dados de forma assíncrona.

Microsserviços vs. Monolitos

Em contraste com os sistemas monolíticos, em que todos os módulos compartilham o mesmo processo de
execução e o mesmo espaço de memória, a arquitetura baseada em micros serviços divide a aplicação em
pequenos processos independentes e autônomos. Essa abordagem mitiga gargalos de desenvolvimento e
implantação ao favorecer a evolução independente por equipes ágeis, viabilizar a escalabilidade
horizontal seletiva dos componentes com maior demanda, tolerar falhas parciais do sistema e permitir
o uso de tecnologias heterogêneas. Para preservar a autonomia dos serviços e evitar acoplamento,
preconiza-se que cada micros serviço faça o gerenciamento exclusivo de sua própria base de dados.
